# Codex implementation prompt — pptxlint v0.1

Build v0.1 of **pptxlint**, a deterministic local CLI quality gate for
PowerPoint files generated by code and AI agents.

Product positioning:

> **pptxlint — ESLint for generated PowerPoint.**
>
> Catch broken layout, invalid OOXML, and presentation-policy violations before
> the deck ships.

The success criterion is:

```bash
npx pptxlint generated.pptx
# exits 1 and tells me exactly why
```

## Read first

Treat these repository documents as normative and keep them synchronized with
the implementation:

1. `docs/product-spec.md`
2. `docs/architecture.md`
3. `docs/implementation-plan.md`
4. `docs/pull-request-plan.md`

When a PPTX/Open Packaging behavior is uncertain, inspect ECMA-376/Open
Packaging Conventions and a minimal fixture before implementing it. Do not infer
OOXML semantics from filenames or one sample deck.

## Scope

Implement:

- Node.js 22 + TypeScript strict + pnpm workspace;
- framework-agnostic `@pptxlint/core`;
- CLI package/binary `pptxlint`;
- JSON configuration;
- exactly the ten v0.1 rule IDs listed below;
- config suppressions;
- baseline mode;
- stylish, versioned JSON, and SARIF 2.1.0 output;
- deterministic exit codes and findings;
- synthetic fixtures, unit tests, integration tests, and packed-package smoke.

Do **not** implement in v0.1:

- web UI;
- REST API or cloud upload;
- database, accounts, auth, billing, or organization policies;
- repair, `--fix`, or any PPTX mutation;
- rendering, screenshots, thumbnails, or visual diff;
- AI features;
- health score;
- font substitution or OS font installation checks;
- PowerPoint/LibreOffice automation;
- `.pptm`, encrypted, or password-protected files;
- public npm publication.

Mark workspace packages `private: true` and use `UNLICENSED` until licensing is
decided. Prefer dependencies with permissive MIT/BSD/ISC/Apache-2.0 licenses;
document any exception before adding it.

## Public core contract

Provide an API equivalent to:

```ts
interface LintInput {
  bytes: Uint8Array;
  displayPath: string;
  inputKey: string;
}

interface LintOptions {
  config: ResolvedConfig;
  baseline?: Baseline;
}

async function lintPptx(
  input: LintInput,
  options: LintOptions,
): Promise<LintReport>;
```

The exact types may evolve, but dependency direction and semantics must remain.

## Shared PPTX context

Build the package model once and share it between rules:

- canonical ZIP entry index;
- lazy cached bytes;
- cached XML parse results;
- content types;
- root and part relationships;
- incoming/outgoing relationship graph;
- slide order from `p:sldIdLst` and relationships;
- slide → layout → master → theme chain;
- local slide shape inventory and z-order;
- slide dimensions;
- geometry and effective text-style resolvers.

Do not re-read the archive or reparse XML for every rule. Match XML by namespace
URI and local name, not by prefix.

External relationships must never be fetched.

## Finding contract

Use a versioned contract equivalent to:

```ts
type Severity = "warning" | "error";

interface FindingLocation {
  part?: string;
  slideNumber?: number;
  slideId?: string;
  shapeIds?: number[];
  shapeNames?: string[];
  paragraphIndex?: number;
  runIndex?: number;
}

interface PptxFinding {
  ruleId: RuleId;
  severity: Severity;
  message: string;
  file: string;
  location: FindingLocation;
  evidence: Record<string, string | number | boolean | string[] | null>;
  fingerprint: string;
}
```

Fingerprints must be deterministic. Include rule ID, normalized input key,
canonical part/slide identity, sorted shape IDs, and a stable rule-specific
discriminator. Do not include message text, severity, measured overlap values,
absolute paths, timestamps, locale-formatted strings, or UUIDs.

Sort all findings and evidence arrays canonically.

## Rules

Implement exactly these rule IDs.

### 1. `package/broken-relationship` — default error

Detect missing internal targets for non-media relationships. Report source part,
relationship part, rId, type, raw target, and resolved target. Exclude known
image/audio/video relationship types so missing media is not duplicated.

### 2. `package/missing-media` — default error

Detect missing internal targets for image, audio, and video relationships.
Report media kind and referencing slide when resolvable. Never download or
invent a replacement.

### 3. `package/malformed-xml` — default error

Detect XML parts that are not well-formed. Cache parse failures. Reject
DTD/external entities. Return a partial report with `analysisComplete: false`
when downstream prerequisites are unavailable; do not emit cascade exceptions.

### 4. `layout/outside-slide` — default warning

Detect locally-authored slide shapes outside slide bounds beyond configured
tolerance. Apply nested group coordinate transforms, flips, scaling, and
rotation. Report transformed bounds, affected edges, outside area ratio, and
threshold. Do not inspect inherited master/layout decorations in v0.1.

### 5. `layout/text-overlap` — default error

Detect significant intersection between two locally-authored, non-empty
text-bearing shapes. Use transformed polygons. Calculate intersection area as a
ratio of the smaller text box. Canonicalize shape pairs. Do not create A/B and
B/A duplicates. Exclude table cells within the same table and an object versus
its own children.

Do not claim pixel-perfect glyph collision; this is text-frame geometry.

### 6. `layout/text-occluded` — default error

Detect a text-bearing shape covered by an opaque shape later in slide z-order.
Only produce high-confidence findings:

- opaque solid fill with known transparency;
- JPEG;
- image known not to contain an alpha channel.

Treat unknown opacity as unknown, not opaque. Report text shape, foreground
shape, text-frame occluded ratio, z-order, and opacity basis. Do not claim
pixel-perfect glyph coverage.

### 7. `text/min-font-size` — default error

Resolve effective stored font sizes through supported run, paragraph, list,
placeholder, layout, master, and presentation style inheritance. Support
separate title/body thresholds. Include provenance in evidence.

Do not invent a size when resolution is incomplete. Findings caused by a stored
autofit scale belong to the specialized rule below and must not be duplicated.

### 8. `text/autofit-scale-below-minimum` — default error

Run only when OOXML contains a valid persisted autofit scale and the base size
is resolved. Normalize the stored scale according to the OOXML specification,
then compute effective size as base size × normalized scale ratio. Report base,
raw scale, normalized scale, effective size, and threshold.

Do not simulate line breaking or font metrics.

### 9. `text/autofit-enabled` — default warning

Detect runtime autofit when no usable persisted scale proves the final size.
Explain that final rendering may depend on installed font metrics. Do not emit
this in addition to `text/autofit-scale-below-minimum` for the same shape.

Never output a guessed point size.

### 10. `fonts/allowed` — default error when configured, otherwise off

Resolve explicit and theme fonts for Latin, East Asian, and Complex Script
slots. Compare them with the configured allowlist. Support an `unresolved`
option with `ignore`, `warning`, or `error` behavior. Do not inspect fonts
installed in the operating system.

## Geometry accuracy

Keep source dimensions in EMU. Implement and test affine transforms for nested
groups, child coordinate spaces, rotation, and flips. Use transformed polygons
for clipping/intersection and stable point/ratio values for evidence.

Unknown geometry must not become a false precise finding. Prefer a documented
unsupported state and fixture-backed TODO over a guessed transform.

## Configuration

Support `.pptxlintrc.json` and `--config`. Without an explicit path, search for
the config from the current working directory upward. Apply one resolved config
to all input files.

Support:

- built-in `recommended` preset;
- `off`, `warning`, and `error` rule severities;
- typed rule options;
- default `failOn: error`;
- CLI `--fail-on` override;
- unknown rule/option as config error and exit 2.

Representative config:

```json
{
  "extends": ["recommended"],
  "failOn": "error",
  "rules": {
    "layout/outside-slide": [
      "warning",
      { "tolerancePt": 2, "minOutsideRatio": 0.05 }
    ],
    "layout/text-overlap": ["error", { "minOverlapRatio": 0.2 }],
    "text/min-font-size": ["error", { "defaultPt": 12, "titlePt": 20 }],
    "fonts/allowed": [
      "error",
      {
        "families": ["Aptos", "Arial", "Inter"],
        "unresolved": "warning"
      }
    ]
  },
  "ignore": [
    {
      "rule": "layout/text-overlap",
      "slide": 3,
      "shapeIds": [18, 22],
      "reason": "Intentional label overlay"
    }
  ]
}
```

## Suppressions

Implement exact config suppressions in v0.1. Match by rule plus at least one of:

- input relative path;
- slide number or persistent slide ID;
- shape ID(s);
- part name.

Canonicalize shape pairs regardless of order. Apply suppressions before baseline
comparison. Report suppressed count and unused-suppression metadata. Do not add
regex/fuzzy matching or notes/custom-metadata suppression.

## Baseline mode

Support:

```bash
pptxlint legacy.pptx --write-baseline .pptxlint-baseline.json
pptxlint legacy.pptx --baseline .pptxlint-baseline.json
```

The baseline is deterministic versioned JSON containing tool major/schema
version, normalized input keys, fingerprints, rule IDs, and minimal locations.
It must not contain PPTX bytes, extracted slide text, timestamps required for
comparison, or absolute paths.

Classification:

- current + baseline → existing;
- current only → new;
- baseline only → resolved.

Only new unsuppressed findings participate in exit policy. Incompatible
baseline schema/tool major returns exit 2.

## Formatters

Implement:

- `stylish` for humans;
- versioned `json` for automation;
- SARIF 2.1.0 for CI/code-scanning systems.

SARIF must publish rule descriptors, PPTX artifact URIs, logical slide/shape
locations, evidence properties, and partial fingerprints. Do not claim line-level
annotation or slide preview: PPTX is a binary artifact. Those require a future
GitHub Check/App and renderer.

Machine formats must not contain ANSI. With a machine formatter, stdout contains
only the selected format; diagnostics go to stderr. Support `--output-file`.

## Exit codes

- `0`: no new unsuppressed findings at `failOn` severity or above;
- `1`: at least one new unsuppressed gating finding;
- `2`: CLI usage, invalid config/baseline, unreadable/unsupported input, or
  internal failure.

An explainable partial analysis caused by malformed XML remains a lint report;
an unexplained incomplete analysis is an internal error.

## Security

Add limits for:

- 10,000 ZIP entries;
- 1 GiB declared total uncompressed size;
- 256 MiB per uncompressed entry;
- 20 MiB per XML part;
- 200:1 compression ratio per entry;
- actual uncompressed bytes in addition to declared metadata.

Protect against canonical path traversal, duplicate entries, ZIP bombs,
DTD/entities, truncated archives, and external relationship fetches. Never
modify the input PPTX. Do not include full slide text or absolute paths in
default machine output.

## Tests and fixtures

Generate synthetic PPTX fixtures from readable templates/builders. Do not rely
only on real PowerPoint files and do not commit proprietary decks.

Every rule requires:

- clean negative fixture;
- positive fixture;
- threshold boundary where relevant;
- malformed prerequisite case;
- deterministic fingerprint assertion;
- severity/off config override;
- suppression match/non-match;
- baseline new/existing transition.

Add pure unit tests for relationship path resolution, affine transforms,
polygon intersection, scale normalization, style inheritance, fingerprints,
baseline comparison, and exit policy.

Add CLI integration tests for code 0/1/2, multi-file input, stdout/stderr,
config errors, baseline workflow, JSON, SARIF, and packed-package install/execute.

Use small injected thresholds for ZIP-bomb/large-media tests. Generate the
50 MiB/100-slide benchmark rather than committing it.

## Implementation order

Follow the ten PR boundaries in `docs/pull-request-plan.md`:

1. workspace and CI;
2. ZIP/XML adapters and fixtures;
3. OPC/PresentationML context;
4. lint engine, config, package rules, CLI alpha;
5. geometry and outside/overlap rules;
6. high-confidence occlusion;
7. text styles, autofit, and allowed fonts;
8. suppressions and baseline;
9. JSON/SARIF and packed CLI UX;
10. security, corpus calibration, and release preparation.

Keep all root checks green after every stage. Do not begin a later consumer
layer to hide an incomplete core rule.

## Final validation

Before declaring v0.1 complete:

1. Run all quality gates on a clean checkout.
2. Demonstrate a clean file with exit 0.
3. Demonstrate package, layout, and text findings with exit 1.
4. Demonstrate invalid config/input with exit 2.
5. Demonstrate suppression of an intentional overlap.
6. Demonstrate baseline write, existing issues, a new issue, and resolved issues.
7. Produce and validate JSON and SARIF outputs.
8. Install the packed CLI into a clean temporary consumer and run it.
9. Record benchmark time and peak RSS for a generated 50 MiB/100-slide deck.
10. Calibrate defaults on at least 30 non-proprietary or locally held real decks
    from at least three generator/source families; commit only anonymized
    aggregate results.

For default-error layout rules, target at least 90% precision on the labeled
calibration corpus. If a rule misses the target, narrow it or lower its default
severity instead of hiding the limitation.

## Final report

Summarize:

- implemented rules and their default severities;
- supported config/suppression/baseline behavior;
- output formats and exit codes;
- fixture/integration/package test results;
- performance/corpus calibration evidence;
- known blind spots, especially rendering-dependent behavior;
- deferred roadmap items.

The final repository must deliver a trustworthy linter, not a broad presentation
platform. If a finding cannot be proven from saved OOXML, say so explicitly and
do not fabricate precision.
