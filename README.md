# pptxlint

> **ESLint for generated PowerPoint.**

`pptxlint` is a deterministic, local-first CI gate for `.pptx` files generated
by code or AI agents. It detects broken package relationships, stored layout
problems, unsafe typography, and font-policy violations without opening
PowerPoint or making network requests.

```text
generated.pptx

  slide 7 / shape 14
  error   text/autofit-scale-below-minimum
  Stored fontScale reduces text from 21pt to 8.4pt; the configured minimum is 12pt.

✖ 1 new problem (1 error, 0 warnings)
```

The public beta is Apache-2.0 licensed and supports Node.js `^22.13.0` and
`^24.0.0`. Prereleases use the npm `next` dist-tag.

## Five-minute start

Install the CLI in the project that generates your presentation:

```sh
npm install --save-dev pptxlint
npx pptxlint build/deck.pptx
```

No config is required. The recommended rules run by default, errors fail the
command, and warnings remain visible without failing the build.

Copy the broken deck shipped in the installed CLI package, then lint it:

```sh
node -e "require('node:fs').copyFileSync(require.resolve('pptxlint/example'), 'public-broken-deck.pptx')"
npx pptxlint public-broken-deck.pptx
```

Its deterministic outputs are committed as
[stylish text](examples/public-broken-deck.expected.txt) and
[versioned JSON](examples/public-broken-deck.expected.json). The deck itself is
generated by `pnpm example:build`; CI verifies that its bytes and reports remain
reproducible.

## PptxGenJS

Install the generator and linter:

```sh
npm install --save-dev pptxgenjs pptxlint
```

Create `generate-deck.mjs`:

```js
import { mkdir } from "node:fs/promises";

import pptxgen from "pptxgenjs";

await mkdir("build", { recursive: true });

const pptx = new pptxgen();
pptx.layout = "LAYOUT_WIDE";
pptx.author = "Example team";

const slide = pptx.addSlide();
slide.addText("Quarterly review", {
  x: 0.7,
  y: 0.5,
  w: 8,
  h: 0.6,
  fontFace: "Aptos",
  fontSize: 28,
  bold: true,
});

await pptx.writeFile({ fileName: "build/deck.pptx" });
```

Generate, then lint the exact artifact that will ship:

```sh
node generate-deck.mjs
npx pptxlint build/deck.pptx
```

## python-pptx

Install the Python generator and the Node.js CLI:

```sh
python -m pip install python-pptx
npm install --save-dev pptxlint
```

Create `generate_deck.py`:

```python
from pathlib import Path

from pptx import Presentation
from pptx.util import Inches, Pt

output = Path("build/python-deck.pptx")
output.parent.mkdir(parents=True, exist_ok=True)

deck = Presentation()
deck.slide_width = Inches(13.333)
deck.slide_height = Inches(7.5)
slide = deck.slides.add_slide(deck.slide_layouts[6])
box = slide.shapes.add_textbox(Inches(0.7), Inches(0.5), Inches(8), Inches(0.6))
run = box.text_frame.paragraphs[0].add_run()
run.text = "Quarterly review"
run.font.name = "Aptos"
run.font.size = Pt(28)
run.font.bold = True
deck.save(output)
```

```sh
python generate_deck.py
npx pptxlint build/python-deck.pptx
```

## GitHub Actions and SARIF

Add `pptxlint` to `devDependencies`, make `npm run build:deck` generate
`build/deck.pptx`, then commit this workflow as
`.github/workflows/pptxlint.yml`:

```yaml
name: pptxlint

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read
  security-events: write

jobs:
  lint-deck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v6
        with:
          node-version: 24
          cache: npm

      - run: npm ci
      - run: npm run build:deck

      - name: Lint generated presentation
        id: pptxlint
        continue-on-error: true
        run: >-
          npx --no-install pptxlint build/deck.pptx
          --format sarif
          --output-file pptxlint.sarif

      - name: Preserve SARIF as an artifact
        if: ${{ always() && hashFiles('pptxlint.sarif') != '' }}
        uses: actions/upload-artifact@v4
        with:
          name: pptxlint-sarif
          path: pptxlint.sarif

      - name: Upload SARIF to code scanning
        if: ${{ always() && hashFiles('pptxlint.sarif') != '' }}
        continue-on-error: true
        uses: github/codeql-action/upload-sarif@v4
        with:
          sarif_file: pptxlint.sarif

      - name: Enforce the lint result
        if: ${{ always() }}
        shell: bash
        run: |
          if [ "${{ steps.pptxlint.outcome }}" = "failure" ]; then
            exit 1
          fi
```

The lint step is temporarily allowed to continue so the SARIF file can be
uploaded; the final step restores the failing job result. A `.pptx` is a binary
artifact, so SARIF identifies the file and logical slide/shape locations but
cannot provide source-line annotations or slide previews. GitHub code-scanning
availability for private repositories depends on the repository's GitHub Code
Security entitlement; the uploaded artifact and final exit gate work as the
fallback.

## Configuration, suppressions, and baselines

Create `.pptxlintrc.json` only when the defaults need adjustment:

```json
{
  "$schema": "https://unpkg.com/@pptxlint/core@0.1.1/dist/schemas/pptxlint.schema.json",
  "extends": ["recommended"],
  "failOn": "error",
  "ignore": [
    {
      "rule": "layout/text-overlap",
      "slide": 3,
      "shapeIds": [18, 22],
      "reason": "Intentional label overlay"
    }
  ]
}
```

Use a baseline to accept current debt while continuing to fail on new
findings:

```sh
npx pptxlint legacy.pptx --write-baseline .pptxlint-baseline.json
npx pptxlint legacy.pptx --baseline .pptxlint-baseline.json
```

Suppressions are exact and are applied before baseline comparison. Baselines
store portable input keys and stable finding fingerprints; they do not use
fuzzy matching.

## Rules and output contracts

The beta includes these rule IDs:

1. `package/broken-relationship`
2. `package/missing-media`
3. `package/malformed-xml`
4. `layout/outside-slide`
5. `layout/text-overlap`
6. `layout/text-occluded` (opt-in)
7. `text/min-font-size`
8. `text/autofit-scale-below-minimum`
9. `text/autofit-enabled`
10. `fonts/allowed` (opt-in policy)

Formats are `stylish`, `json`, and `sarif`. JSON config, report, and baseline
schemas ship in `@pptxlint/core` and are also available from the versioned URLs
under [`schemas/`](schemas/).

Exit codes are stable:

- `0`: analysis completed and no finding reached `failOn`;
- `1`: analysis completed and at least one finding reached `failOn`;
- `2`: invalid invocation/configuration or incomplete analysis.

The stable beta contracts are rule IDs, configuration/report/baseline schemas,
fingerprints, and documented CLI behavior. The broad TypeScript exports from
`@pptxlint/core` remain a beta API until 1.0 and may change in a minor release.

## Limitations

- pptxlint analyzes stored OOXML; it does not render slides.
- It cannot promise pixel-perfect text reflow or exact font substitution.
- `layout/text-overlap` is advisory and defaults to warning after real-deck
  calibration; `layout/text-occluded` is opt-in.
- It does not repair files, clean up decks, produce visual diffs, or call
  PowerPoint.
- Changing persistent slide or shape IDs in a generator can produce new
  fingerprints even when the visible content looks similar.

## Development

The workspace uses pnpm 10.24.0 and supports Node.js 22 and 24:

```sh
npm install --global pnpm@10.24.0
pnpm install
pnpm build
pnpm pptxlint --help
```

Run the complete local gate:

```sh
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm test:integration
pnpm test:example
pnpm benchmark
pnpm test:package
```
